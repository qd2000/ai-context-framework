这些规则适用于代码、脚本、构建、调试和重构任务。

## 修改前

1. 先理解现有结构和调用关系，不要凭空引入新抽象。
2. 优先复用项目已有工具、目录约定和命名风格。
3. 如果是修 bug，先确认可复现信号或最小失败路径。
4. 如果是重构，先确认已有测试或补充能锁定行为的最小回归测试。

## 修改中

1. 保持 diff 小、可回退、聚焦当前任务。
2. 不修改无关文件，不格式化无关内容。
3. 不新增第三方依赖，除非用户明确要求或已有项目规则允许。
4. 删除重复逻辑优先于增加新层。
5. 注释只解释不明显的意图、约束或边界，不复述代码。

## 修改后

1. 运行与改动范围匹配的检查：lint、typecheck、单元测试、集成测试或 CLI 自检。
2. 如果不能运行某项验证，说明原因和剩余风险。
3. 汇报时列出变更文件、验证结果和已知限制。
