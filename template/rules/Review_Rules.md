这些规则适用于代码评审、方案评审、架构评审和风险审查。

## 评审重点

1. 先指出最可能失败的地方。
2. 优先关注事实错误、行为回归、缺失验证、维护成本和边界不清。
3. 对每个问题说明影响范围和触发条件。
4. 明确区分确定问题、风险和信息不足。
5. 不用安慰性措辞掩盖风险。

## 输出顺序

1. 结论或总体风险等级。
2. 问题清单，按严重程度排序。
3. 需验证的假设。
4. 信息不足之处。
5. 可执行的修复建议。

## 评审约束

1. 不把个人偏好写成硬性问题。
2. 不要求大规模重写，除非现有结构已经无法支撑目标。
3. 如果建议新增机制，说明它替代了哪类重复人工维护。
4. 如果建议保持现状，也要说明接受的风险。
