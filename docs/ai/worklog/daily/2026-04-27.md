## 有价值的结论

- worklog 和 ADR 的创建及索引更新已进入确定性 CLI 流程，Python 验证入口统一为 uv run python。
- Current_Task 的创建和重置已进入确定性 CLI 流程。
- Sources_Index 的新增和更新已进入确定性 CLI 流程。
- 会话结束回写建议的暂存已进入确定性 CLI 流程，默认只生成可审阅草案。
- 可安装入口、上下文自动发现和 `acf status` 已进入确定性 CLI 流程；AI 在项目子目录中可以省略 `docs/ai` 路径。
- JSON 输出、dry-run、changed files 和写后检查已进入确定性 CLI 流程，AI 可更稳定地判断命令结果。
- JSON 输出基础字段契约已进入确定性 CLI 流程，AI 可依赖 `schema_version`、`ok`、`error_code` 和 `next_actions`。
- exit code 和错误分类已进入确定性 CLI 流程，AI 可区分 check_failed、input_error、safety_refused 和 runtime_error。
- 模板打包文件列表同步已进入 check 和单元测试覆盖，后续新增模板文件时不应只改 `template/`。
- init 的根薄入口生成已进入确定性 CLI 流程，已有根入口默认不覆盖。
- minimal 真实实例不再保留 ADR/worklog 占位模板文件，真实条目通过 `new adr` 和 `new worklog` 生成。
- `simplify` 应保留真实历史文件，但不保留产品模板占位文件。
- `template/` 是产品模板源，不应吸收本仓库 dogfooding 专属事实；后续模板变更应先判断是否具备通用性。
- acf 的长期方向是上下文文件 API：主要服务 AI 的确定性上下文维护，不做通用 Markdown 编辑器、常驻 runtime 或语义裁决系统。
- 安全结构化编辑第一版已进入确定性 CLI 流程，可减少 AI 手工拼接整文件造成的格式漂移。
- section 编辑需要识别并保留 section 末尾的 `---` 分隔线，否则真实文档追加会落到分隔线后面。
- CLI 用法提示适合放在默认入口的短发现层，完整参数仍由 `acf --help` 和 System Manual 承担。
- minimal 上下文不一定包含 System Manual，入口中不能把不存在的系统手册路径写成上下文内 Markdown 引用。
- 任意目录可直接运行 `acf` 依赖 PATH 安装；`acf status` 能否成功还取决于当前目录是否位于某个上下文项目内。
- 后续上下文计划维护应优先使用 `acf edit` 的结构化写入能力，避免 AI 手工重写整文件造成格式漂移。
- `acf edit` 不应为了 dogfooding 临时突破 context-root 限制；如需维护 `docs/ai` 外文档，应先设计项目级安全编辑能力。
- usage event log 可以作为跨项目 dogfooding 评测的前置观测能力，但它不是事实源，也不替代整理后的 daily worklog。

如果这些结论已经成为当前事实，请同步更新到 `active/Context.md`。
