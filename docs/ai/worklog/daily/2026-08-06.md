## 有价值的结论

- Primary 是否 dirty 不是合并安全性的决定条件；真正需要保护的是来源提交完整性、候选写入集合、primary 本地状态稳定性和 promotion 原子性。
- staged 内容不会进入 integration worktree 中已经生成的候选 commit；因此 staged 不应被一律拒绝，但必须记录 index OID、working-tree摘要并做碰撞保护。
- 完全相同的 untracked/ignored 重叠可以安全收敛，但 Git 自身仍会拒绝覆盖，因此需要仅针对已证明等价路径的可恢复 quarantine。
- `git status clean` 不代表 ignored 结果已保存；artifact handoff 必须是独立于 Git clean 的正式门禁。
- 冲突与 post-check 失败应发生在 integration worktree中，让 main 保持未改变，修复后通过 operation ID继续。
- close 需要像 merge 一样具备持久 journal、有限重试和部分成功恢复，不能把 Windows 文件占用当作终态失败。

## 已知边界

- ACF 不自动猜测 ignored 文件重要性；未配置或未显式声明的路径保持 unknown 并阻止 promotion。
- ACF 不自动选择冲突的 ours/theirs；真实冲突保留在 integration worktree 等待人工或 agent 解决。
- 持续 primary churn 超过 8 次、不可证明安全的跨主机 stale lock、持久路径碰撞和确定性测试失败会进入可恢复暂停或人工处理。
- FCC upgrade dry-run显示其 AGENTS/System Manual 需要追加兼容说明；本轮保持只读，没有在 dirty main 中自动应用。
