## 有价值的结论

- 机械检查全绿不等于产品健康：本次修复的文档漂移、运行态污染与 issue 滞留，`check --strict`、`doctor`、`audit context` 此前全部没有报出。
- 测试污染真实运行态是可复现的代码缺陷而非环境噪声：隔离 `ACF_HOME` 后真实命名空间数量从 551 降到 138，且 smoke 运行前后目录集合不变。
- 产品 issue 生命周期可以完全脱离 active continuation：occurrence 留在各项目 usage log，处置写入用户级 append-only 台账即可，并能与既有 `continuation_issue_resolution` 事件共存。
- ACF 侧 owner-context 传输本身可用：隔离 fixture 中 `assert-owner`、`progress`、`release --handoff` 全部通过，说明真实网页链路若失败也不是 ACF credential 校验的问题。
- 隔离 `ACF_HOME` 必须放在被测 Git worktree 之外，否则 workspace digest 会因扫描到 continuation state 而失败。

如果这些结论已经成为当前事实，请同步更新到 `active/Context.md`。

## 无效尝试

- 把临时 `ACF_HOME` 放在被测 worktree 内：`continuation claim` 返回 `workspace_digest_failed`，因为 continuation state 会被 workspace digest 扫描到。
- 用「真实 `ACF_HOME` 目录 mtime 完全不变」作为回归断言：并发的外部 continuation（例如 WS080）会合法更新其他项目命名空间，导致断言偶发失败；改为按验收标准断言「命名空间集合不变」。
