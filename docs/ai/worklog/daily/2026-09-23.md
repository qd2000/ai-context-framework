## 有价值的结论

- `release_check --mode full` 在本机会话里前台运行会因长时间无输出被判空闲中断；改为后台 `nohup` + 轮询日志后，用 `--skip-tests --skip-upgrade-matrix` 单独跑构建与隔离安装段（unittest 与 `upgrade_matrix --mode full` 已分别跑绿），避免整体空转。
- `dist/` 残留历史版本制品会让 `artifact_files` 报 `expected exactly one wheel and one sdist`；发布验收应省略 `--output-dir` 走临时目录，防止历史 dist 混入当期制品判定。
- 发布闭合的决策顺序仍应是「验收 → 碰撞探测 → tag → 发布」：本次在授权前只完成前两步，tag 与发布保持未执行，避免出现 CHANGELOG 已写"发布完成"而实际未落地的假事实。

如果这些结论已经成为当前事实，请同步更新到 `active/Context.md`。
