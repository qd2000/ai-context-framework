## 有价值的结论

- parser composition 的关键不是搬运代码而是保持 handler 身份：CLI 绑定的是 runtime_parts 的 deps 适配器，所以 register_*_parser 必须显式注入 handler；命令树快照护栏（210 条路径的 options/dest/nargs/default/choices + handler 限定名）是唯一能可靠发现这类漂移的手段，本次它确实第一时间抓到了 4 处。

如果这些结论已经成为当前事实，请同步更新到 `active/Context.md`。

- 下移是逐组可验证的机械操作，但每组都必须显式注入 runtime_parts 的 deps 适配器作为 handler；命令树快照让每组只需 0.2 秒即可确认零漂移，整轮行为验证仍由 test_cli 与杂项批次兜底。

- 命令组下移的真正约束不是代码搬运而是 handler 归属：CLI 绑定 runtime_parts 的 deps 适配器，所以每个 register_*_parser 都必须显式注入 handler，快照护栏是唯一能可靠发现漂移的手段；对超大命令组（workstream 29 个 handler、continuation 顶层组）改为独立 *_parsers 模块并做缺失 key 校验，避免把已接近 2000 行门禁的命令模块推过去。

- 顶层 shim 的“同步”本质是把 ROOT 变化传播给被注入的 part 模块；把它收成一个公开、幂等的 set_root 入口后，shim 只需判断差异再调用，既保留 legacy 契约又彻底切断对私有全局与私有同步函数的依赖，同时可用源码断言把“不写内部”固化为契约。
