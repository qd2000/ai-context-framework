## 新发现的问题

- 并行执行多个会写入同一 `active/Task_Plan.md` 的 `acf plan add-task` 会导致 ID 分配顺序不可预测；后续应考虑文件锁、乐观并发检查，或在文档中明确写命令不要并行作用于同一文件。
- `acf plan status --json` 的 `next_task` 当前只返回第一个 Pending 子任务，没有考虑依赖关系和当前 Active 任务，容易误导下一步推荐。

- Knowledge 草案质量检查偏弱：当前 check 只验证结构和引用，无法识别“待补充”这类语义空洞内容。建议后续至少在 strict 模式下对 Knowledge 草案中的“待补充/未分类/无。”等默认值给 warning 或 error。
- 任务计划完成态需要更顺手：子任务 Done 后，大任务计划仍是 Active，归档计划需要 `--force`。建议新增 `acf plan complete` 或在所有子任务完成后由 `task done`/`plan status` 给出 next_actions。

- P2：`acf knowledge draft` 的中文标题 slug 会退化为 `item`，例如生成 `worklog/knowledge-drafts/2026-04-29-item.md`；中文项目需要更好的文件命名策略，如保留拼音/短 hash/允许安全 Unicode。
