## 有价值的结论

- Workstream 应定位为可选并行目标线协作契约，不是 agent runtime；轻量 front matter 适合新增状态型文档局部试用，不适合全量迁移现有叙述型文档。
- Workstream 详情文件比 Task_Plan 更适合承载并行目标线的边界、读取范围、写入范围、合并请求和状态流转。
- ReadyToMerge 合并请求需要包含目标文件、候选变更、人工判断点、冲突和验证结果，才能让主 agent 不读全过程也能合并。
- Front matter parser 应保持独立于 Workstream；schema 由 Workstream、ADR、Knowledge 等调用方传入，parser 只负责极小 YAML 子集和稳定正文保留。
- Workstream 与 front matter 的兼容策略必须 optional first：旧项目、旧 ADR、旧 worklog、旧 Knowledge 没有新结构或 metadata 时不应被 upgrade/check 打扰。
- Workstream CLI 实现前应先按规格测试命令契约，避免先写命令再返工状态转换、scope 冲突和 optional check 触发条件。

如果这些结论已经成为当前事实，请同步更新到 `active/Context.md`。
