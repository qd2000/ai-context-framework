## 边界说明

本 Workstream 使用强隔离协作协议。AI 执行前应先运行 `acf workstream context WS018` 获取专属上下文入口；完成、ready、done 或切换状态前，应优先运行 `acf workstream guard WS018 --files <本次修改文件...> --json` 对本次文件集做强验收。裸 guard / `--from-git` 只用于快速查看当前 git diff；旧式整工作区排他检查需显式使用 `--workspace --strict-workspace`。

- `read_scope` 是允许读取的默认上下文入口。
- `write_scope` 是允许直接修改的范围。
- Task Workstream 不直接修改 authority 文件；需要主线合并时先写 merge request。
- active workstream 默认禁止重叠写入；共享文件必须显式使用 `shared:` 并指定 merge_owner 或 serial coordination。

## 当前发现

- v0.0.3.97 的两个 PyPI 制品均不含 LICENSE，wheel METADATA 也没有任何 License 字段：该版本 tag `33163fc8` 早于 LICENSE 落地提交 `155480b`，因此 `.97` 在许可证层面是残缺发布。这是必须继续发布 v0.0.3.98 的真实原因，而非为了绕过问题。
- `pyproject.toml[project]` 当前完全没有 license 字段，`[build-system] requires = ["setuptools>=61"]` 不支持 PEP 639。`uv build` 会就地重写 `ai_context_framework.egg-info/`（追加 `License-File: LICENSE`、`Dynamic: license-file`，SOURCES.txt 增加 LICENSE 行），属于构建期非确定性副作用，需要用显式 PEP 639 声明消除。
- `.97` 的 wheel/sdist 摘要已与 PyPI `digests.sha256` 逐字符核对通过，可作为不可变基线保存。

- 发布：`Publish release to PyPI` `run_number=39 attempt=2 completed success`，head `33163fc8`，即 attestation 要求的 attempt 2 / success。
