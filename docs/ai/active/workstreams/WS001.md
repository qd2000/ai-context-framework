# WS001 - Workstream dogfooding gate

## 边界说明

本 Workstream 的读取范围是推荐上下文，不是权限隔离。所有 agent 仍必须遵守项目级 AGENTS、rules 和人工指令。允许修改范围是协作契约，用于避免并行写入冲突。

---

## 目标

验证 Workstream 可选层在没有完整 CLI 的情况下是否能承载一个最小并行目标线，并确认读取规则、详情文件、ReadyToMerge 合并请求和 Done evidence 是否足够清晰。

---

## 非目标

1. 不实现 `acf workstream` 命令。
2. 不引入 runtime、调度器或权限沙箱。
3. 不把 Workstream 变成默认读取层。

---

## 状态流转记录

1. Open：创建最小 Workstream 目标线和详情结构。
2. Active：用该 Workstream 承载 T002 读取规则收敛和 dogfooding 验收。
3. ReadyToMerge：整理合并请求，列出需要写回的入口规则、模板规则和任务板状态。
4. Done：合并 T002 读取规则，记录 evidence，并确认当前没有 Active、Blocked 或 ReadyToMerge workstream。

---

## 当前发现

1. 默认读取规则可以保持轻量：没有 Active、Blocked 或 ReadyToMerge workstream 时，不需要默认读取 Workstreams。
2. Workstream 详情文件比 Task_Plan 更适合承载并行目标线的边界、读取范围、写入范围、合并请求和状态流转。
3. ReadyToMerge 合并请求能减少主 agent 合并时重新阅读全过程的成本，但必须包含目标文件、候选变更、冲突和验证结果。

---

## 合并请求

### 需要合并到哪里

- AGENTS: 补充仅在 Active、Blocked 或 ReadyToMerge workstream 存在时按需读取 Workstreams。
- System Manual: 补充 Workstreams 是可选并行目标线索引。
- Task_Plan: T002 完成后设置 evidence；T007 完成后设置 evidence。
- Worklog: 记录本次 dogfooding 结论。

### 候选变更摘要

1. 模板和 dogfooding AGENTS 默认不把 Workstreams 放入无条件读取路径。
2. `template/` 第一版不默认生成 Workstream 结构，旧项目 upgrade 也不默认启用。
3. Workstream 结构通过显式命令或人工 dogfooding 启用。
4. Done 状态后，Workstreams 索引状态回到 Inactive，避免默认读取噪音。

### 需要人工判断的问题

1. T004 实现时是否让新项目 `acf init` 默认生成空 Workstreams 索引，当前建议否。
2. T004 实现时是否把 Workstream 归档命令放入第一版，当前建议先支持 done/cancel evidence，再实现 archive。

### 已知冲突

无已知写入冲突。本 Workstream 的 authority 写入都由主 agent 在同一轮合并。

### 验证结果

已通过 `uv run acf check docs/ai --strict --json`。

### 建议合并方式

直接保留已写入的 AGENTS、System Manual、Task_Plan 和 Workstream 文件；后续实现 CLI 前，以本 Workstream 作为 dogfooding evidence。

---

## 完成标准

1. 已创建最小 Workstream 索引和详情文件。
2. 已验证 Open -> Active -> ReadyToMerge -> Done 的信息是否能表达清楚。
3. ReadyToMerge 合并请求足以指导主 agent 合并。
4. Done evidence 可追溯。
5. 当前无 Active、Blocked 或 ReadyToMerge workstream，因此默认读取不变重。
