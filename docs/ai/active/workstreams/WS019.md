# WS019 - Ownerless dirty WIP agent-first takeover

## 边界说明

本 Workstream 使用强隔离协作协议。AI 执行前应先运行 `acf workstream context WS019` 获取专属上下文入口；完成、ready、done 或切换状态前，应优先运行 `acf workstream guard WS019 --files <本次修改文件...> --json` 对本次文件集做强验收。裸 guard / `--from-git` 只用于快速查看当前 git diff；旧式整工作区排他检查需显式使用 `--workspace --strict-workspace`。

- `read_scope` 是允许读取的默认上下文入口。
- `write_scope` 是允许直接修改的范围。
- Task Workstream 不直接修改 authority 文件；需要主线合并时先写 merge request。
- active workstream 默认禁止重叠写入；共享文件必须显式使用 `shared:` 并指定 merge_owner 或 serial coordination。

## Context Packet

### Mission

为 ownerless handoff 后的 task-owned WIP 漂移补一条"同一个 Agent 自行审查 + 原子接管"路径：ACF 继续默认阻塞未知变化，但同一个 runner 可以批量审查被保留的现场，并在一次 claim 状态锁内接管已审查的 WIP，全程不修改、不删除、不提交任何一个工作区字节。接管只表示"值得保留并继续处理"，不表示内容正确。

### Forbidden Scope

- 其他 active workstream 的 owned 文件。
- Task Workstream 的 authority 文件直接写入。

### Evidence Required

- 状态迁移到 ReadyToMerge 前必须有合并请求或明确无主线合并说明。
- 状态迁移到 Done 前必须有 evidence 和 merge_resolution。

### Merge Contract

- ReadyToMerge 表示任务产物完成。
- Done 表示合并或处置完成。

## 目标

1. 保持默认 fail-closed：ownerless 期间的未知 task-owned WIP 变化继续阻塞 claim，新增稳定原因码 `workspace_handoff_review_required`，不新增宽泛 `--force`。
2. `doctor` 暴露可审查现场：`handoff_reviewable`、`review_path_count`、`review_paths`、`source_generation`、`observation_digest` 与对应 `next_actions`。
3. 新增 `acf continuation workspace review-handoff`：只读生成按文件指纹绑定的审查包与决策草稿，不改项目文件、不改 manifest、不取得 ownership，支持分组与分页。
4. `acf continuation claim --handoff-review-file` 在同一 state lock 内完成机械验证 + 应用决策 + 写 receipt + 推进 generation + 建 lease/fencing，中间不留被抢先 claim 的窗口。
5. 接管后返回 `handoff_takeover`（`accepted_for_triage`、`required_initial_action=triage_inherited_wip`），generated prompt 在新 generation 第一次有效 checkpoint 前高显著提示继承 WIP 未经证明正确。

6. 同步后的 `Continuation_Control_Design.md`、两份 System Manual、`docs/Automation.md`、README 与 CHANGELOG。

## 当前发现

- 既有 `workspace reconcile-handoff --cleanup` 只覆盖"WIP 已被审计清理成 semantic-clean"这一种收口，无法保留仍然 dirty 但值得继续处理的 WIP；此前 Agent 只能先 commit / stash / revert / 删除现场才能继续，等于用工作区动作偿还控制面缺口。
- drift 判定此前分散在 `observe_handoff` 内；审查包需要与之严格一致，否则会出现"ACF 说漂移、审查包说没漂移"的歧义。现已抽取 `_drift_pairs` 作为单一真相源。
- `continuation_workspace.py` 已接近仓库 agent-friendly 体积上限，新增接管模型拆为 `ai_context_framework/continuation_handoff_review.py`；对应地，命令层把 ownerless 接管、journal（progress/effect）与 setup（init/configure）拆为独立适配器模块。
