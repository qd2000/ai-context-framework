## 当前发现

- ACF v0.0.3.62 已解决 TTL-active 不等价于 runner liveness、stale/orphan classification、generation fencing、durable effect journal 和 formal reconcile/recover；WS008.3 分支已进一步取消 reconcile 对 `git_clean=false` 的 blanket fail-closed，改为消费 bounded workspace ownership manifest/digest。
- stale/orphan runner 的已声明 write intent 与可证明 `runner_owned` WIP 现在可 formal recover 到 generation+1；`baseline_external` / `unexpected_nonoverlap` 原样保留且不进入提交。reconcile receipt 纳入 workspace ownership digest，内容/状态/ownership 漂移会使 receipt stale；无 manifest、generation mismatch、真实路径冲突、不可解释 HEAD、未解决 side effect 或 identity 漂移仍 fail-closed。
- WS008.4A 分支已把 heartbeat/stale/renew timing 解耦，并加入 `standard/long-running` profile、existing-task `configure` 与 generated prompt timing；后续不再把 scheduler interval 当 Gate 截止时间。
- 新的硬约束：`worktree dirty` 不参与 owner liveness、claim/release/reconcile/recover 判断；只使用 path/status/digest ownership、HEAD/effect/identity 等具体证据。正常 Scheduled round 允许携带未提交 `task_owned` WIP release/claim，Git commit 只在自然语义 checkpoint 时创建。
- 同一 worktree 的后续 contention 采用 single-writer + multi-contender：后来的 attempt 先登记 started_at/objective 并 challenge 当前 owner；owner-authenticated ACF activity 可 ACK，timeout 只撤销 ownership 资格而不宣称证明 Agent 死亡，随后仍走 workspace/effect/identity formal reconcile + generation fencing。
- WS008.4C 已落地 bounded 用户级 `coordination.json`：`coordination attempt` 只登记 `claim_candidate` / `contender`，`coordination challenge` 只针对 attempt 已观测到的 fenced owner generation 开启或加入单一 nonterminal challenge；两者都不授予写权限、不宣称 owner 死亡，owner generation 变化会使旧 attempt fail-closed。
- WS008.4D 已把 owner-authenticated continuation activity 接入 challenge response：合法 fenced owner activity 可将 open/timed-out challenge 解析为 `owner_active`，正常 release 解析为 `owner_released`；deadline 到期只产生 `ownership_forfeiture_candidate`，不等价于证明 Agent 死亡。legacy unfenced lease 继续走兼容 renew/release 路径，但不能冒充 generation-bound challenge ACK。
- WS008.4E 已把 challenge timeout 证据接入 formal reconcile/recover：reconcile observation 纳入稳定 coordination digest 与 bounded forfeiture candidates；匹配当前 generation 的 timed-out challenge 可撤销 owner 的 ownership 资格而无需额外宣称 `owner_ended`，但 workspace/HEAD/effect/identity 校验仍全部保留。若旧 owner 在 recover 前 authenticated ACK，coordination digest 漂移会使 receipt `reconciliation_stale`；若 recover 先完成，则 generation+1 fencing 立即拒绝旧 owner，challenge 记录为 `ownership_recovered`。ACK/reconcile/recover 都使用同一 continuation state lock，因此竞态最多产生一个 writer。
- WS008.4F 已把 contention 协议收敛为通用 generated protocol：所有可定位项目的普通 ACF 命令都会 opportunistic 只读提示当前 active owner generation 的 pending challenge，但绝不 ACK；owner-protected continuation 命令在 fenced credential 验证后 authenticated touch，release 解析为 `owner_released`。`acf continuation prompt` 现在完整生成 attempt/challenge、probe、ACK/timeout、formal reconcile/recover、workspace/effect、heartbeat/renew、checkpoint/release 协议，并成为唯一 generic Scheduled Task protocol 权威；项目 wrapper 只保留固定身份与项目特有 Runtime/科学/权限/验收约束。
- WS008.5 adoption preflight 已在四个真实任务上冻结到 `reference/ws008_long_running_dirty_recovery/ADOPTION_MATRIX.md`：WS008 开发版可原位读取 FCC WS079/WS080/WS086 的既有 continuation state 并生成完整 4F prompt，且保留各自 task-specific next_action；其中 WS080/WS086 真实 task-id 分别是 `ws080-fcc-mechanistic-hourly` / `WS086-hourly-continuation`，证明 wrapper 不得假定 task-id 等于 Workstream ID。AStockT_AI qdspc 当前仍安装 v0.0.3.61，WS003 clean/can_claim=true 但生成的是旧协议，同时项目 `Autonomous_Execution.md` 仍复制旧 generic state machine，因此实际 cutover 必须等新稳定版 package smoke + 安装后再执行，不能提前让生产 wrapper 依赖尚未安装的 4F prompt。
