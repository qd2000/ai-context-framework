# WS014 - Post-v0.0.3.92 Stabilization and Product Health

## 边界说明

本 Workstream 使用强隔离协作协议。AI 执行前应先运行 `acf workstream context WS014` 获取专属上下文入口；完成、ready、done 或切换状态前，应优先运行 `acf workstream guard WS014 --files <本次修改文件...> --json` 对本次文件集做强验收。裸 guard / `--from-git` 只用于快速查看当前 git diff；旧式整工作区排他检查需显式使用 `--workspace --strict-workspace`。

- `read_scope` 是允许读取的默认上下文入口。
- `write_scope` 是允许直接修改的范围。
- Task Workstream 不直接修改 authority 文件；需要主线合并时先写 merge request。
- active workstream 默认禁止重叠写入；共享文件必须显式使用 `shared:` 并指定 merge_owner 或 serial coordination。

## 目标

在 v0.0.3.92 发布后完成受控稳定化：收敛权威文档、隔离测试运行态、实现跨项目 issue 独立生命周期与孤儿日志 GC、建立 owner-context 验证协议、落定 ADR-0006 产品边界并收口 CI；不触碰 runtime 全局注入与 continuation 语义。

阶段：

1. 阶段 0：正式建立 WS014（reserve、范围声明、Task_Plan、Current_Task）。
2. 阶段 A：authority 文档收敛 —— 拆分 `docs/Automation.md` 当前合同与历史说明，撤回 WS012 作为 issue owner 与 Observer 活跃执行路线，修正过期 Trusted Publishing 表述；`active/Context.md` 收敛到约 80–120 行并去掉机器绝对路径、固定版本数字与 AGENTS 两层结构整段；WS013 详细计划移入 `archive/plans/` 并更新引用。
3. 阶段 A2：反馈与路线对齐 —— F015/F017/F019 处置；`Product_Roadmap.md` 阶段状态修正；`Top_Level_Implementation_Gap.md` 六域矩阵重建。
4. 阶段 B：smoke 运行态隔离与日志治理 —— 每个 scenario 强制隔离 `ACF_HOME`；no-pollution 回归；`acf log gc --dry-run/--apply`（严格白名单）；`log issues --all-projects` 分页/摘要；538 个失效命名空间清理。
5. 阶段 C：issue 生命周期与 owner-context —— `acf log issue list|show|resolve|supersede|reject|reopen` 独立命令组（用户级台账）；9 条 open issue 逐条 triage 收口；隔离最小 continuation fixture 与 owner-context 可重复验证协议。
6. 阶段 D：ADR-0006「ACF Core 与 Operations Control Plane 的边界」（仅设计）。
7. 阶段 E：CI 收口 —— actions 固定不可变 SHA；release workflow 依赖必需 CI（含 Windows package smoke）。
8. 阶段 F：版本与 CHANGELOG 收敛、全部验收命令、WS014 closeout 归档。

明确不做：runtime 全局注入解耦（后续独立 Workstream）、通用 hunk 级别所有权系统、高风险 semantic audit 扩张、System Manual marker 共享区块同步机制、`acf maintenance status` 综合入口与 `audit context` 总文件预算 candidate。
