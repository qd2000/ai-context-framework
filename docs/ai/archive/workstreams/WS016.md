## 目标

解耦 ACF CLI 的 runtime 全局注入：把 8 个 runtime_parts 与 runtime 之间的 __dict__ 双向合并替换为显式 __acf_exports__ allowlist 与同名冲突 fail-closed；把 commands/workstream.py 的 28 处 per-call _bind 替换为显式 RuntimeContext；把 build_parser 内联命令组分批下移为 register_*_parser；移除 acf.py 对 runtime 私有全局的写入。全程保持对外 CLI 命令/参数/JSON 契约、退出码与 help 文本不变。

## 当前发现

无。

第 1 步（allowlist + fail-closed）已完成并通过全量门禁。关键实测：runtime 公开名 769 -> 531、runtime.py 1988 -> 1979 行；8 个 runtime_parts 自有名合计 447，跨模块同名 2 个（annotations/re）但均为同一对象；消费侧 workstream.py 82 名、workstream_reserve.py 13 名；最小必需导出集 202 名。同时确认一条隐藏动态依赖：archive_workstream.py 的模块级 __getattr__（PEP 562）会把 commands/workstream.py 的公开 helper 惰性转发到 runtime/acf，因此必须在契约中显式保留而不是当作普通 dunder 丢弃。

第 2 步（RuntimeContext + 冻结绑定）完成。消费侧注入面从合并后的 531 名收窄到 workstream.py 82 名、workstream_reserve.py 13 名，并改为构建一次后冻结；28 处 per-call _bind 全部替换为 _ensure_bound，原始 _bind（含刷新与 _MODULE_OWNED_NAMES 遮蔽语义）保持不变以免破坏既有契约测试。降级记录：本仓库 Python LSP 无 documentSymbol provider，语义引用分析改用既定 ast 静态分析（等价证据），并额外核验所有对 commands/workstream.py helper 的外部调用都先经显式绑定。

T005 第 3 步关键发现：CLI 原本把 review/audit/curate/doctor/draft/feedback/human/writeback/task/archive/linkify/link/decisions 的 handler 绑定到 runtime_parts 的 deps 适配器，而不是命令模块里的同名函数。因此 register_*_parser 必须把 handler 作为参数注入；直接引用模块内同名函数会造成 handler 身份漂移（会导致 deps 缺失）。命令树形状快照护栏在第一次尝试时立刻抓到了这 4 处漂移，证明该护栏是这一步的必要条件。

T005 收口事实：build_parser 已无内联 parser（0 处 subparsers.add_parser），31 处 register_*_parser 组合调用，runtime.py 838 行。超大组落点规则：命令模块超 1900 行时，解析器注册改放独立 *_parsers 模块（workstream_parsers.py、continuation_group_parsers.py），单命令组仍留在其命令模块内。
