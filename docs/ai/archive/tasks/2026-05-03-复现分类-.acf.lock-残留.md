### F014 复现分类结果

| 场景 | 结果 | 分类 |
|---|---|---|
| 正常串行读：`status` / `check --strict` | 执行前后 `docs/ai/.acf.lock` 均不存在 | 非问题 |
| 正常串行写：临时上下文 `plan init` | 写入成功后 `.acf.lock` 不残留 | 非问题 |
| 正常并发撞锁：持锁方存活时另一个写命令执行 | 被拒绝写命令返回 `safety_refused`；持锁方仍存活时锁存在；持锁方正常退出后锁消失 | 非 CLI 清理 bug |
| 异常硬中断：持锁进程被强制杀死 | 锁文件保留，内容含 `pid` 和 command | 运行态副作用 |

结论：本轮没有复现“正常并发拒绝后残留”。`.acf.lock` 残留只在持锁进程被硬中断时出现，归类为异常中断运行态副作用；不需要立即开 CLI 修复任务。后续可选改进是补充清理提示或仓库卫生规则，但不阻塞 `v0.0.3.17` 扩大试点。
